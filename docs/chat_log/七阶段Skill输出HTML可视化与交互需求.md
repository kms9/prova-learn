# 七阶段 Skill 输出 HTML 可视化与交互需求

> 状态：实施基线  
> 调研与评估日期：2026-07-27  
> 适用范围：S1—S7 个性化学习阶段 Skill  
> 真值源：各阶段 JSON 移交信封及其 `positive_artifact`

## 1. 背景与问题

现有七阶段 Skill 已经能够产出结构化 JSON，并通过共同移交信封传递门禁、证据、处理记录、质量评估和阶段正向工件。这些输出适合机器校验和下游 Skill 消费，但不适合学习者、教学设计者或审查者快速完成以下任务：

- 判断当前处于哪个阶段、门禁是否通过、下一步路由是什么。
- 从大量字段中快速定位关键结论、证据缺口、依赖关系和风险。
- 理解大纲、知识点、证据、学习前沿、教学交互与掌握判定之间的关系。
- 在不修改权威 JSON 的前提下筛选、展开、比较和形成待回传的交互草稿。
- 以可离线、可打印、可复验的形式查看一次运行的完整结果。

本需求为每个阶段增加一个 HTML 派生视图。HTML 不是新的业务真值源，也不替代 JSON Schema、门禁或确认协议。

## 2. 调研结论

### 2.1 信息架构

页面采用“总览 → 聚焦与过滤 → 按需详情 → 导出子集或草稿”的交互顺序。该顺序对应 Shneiderman 的信息可视化任务分类：overview、zoom、filter、details-on-demand、relate、history 和 extract。来源：[The Eyes Have It](https://www.cs.umd.edu/~ben/papers/Shneiderman1996eyes.pdf)。

共同页面外壳固定为：

1. 阶段、运行、状态和真值源提示。
2. 总览。
3. 阶段详情。
4. 证据与追溯。
5. 质量与门禁。
6. 原始 JSON。
7. 交互草稿导出和下一步路由。

阶段差异集中在“总览”和“阶段详情”的核心视图中，不能把七个阶段统一降级成通用 JSON 浏览器。

### 2.2 本地与离线能力

页面必须是单文件 HTML，不引用 CDN、远程字体、远程脚本、远程图片或外部 API。页面支持两种数据装载方式：

- Skill 生成页面时，把本次规范 JSON 安全嵌入 `application/json` 数据块。
- 用户从浏览器明确选择或拖入本地 JSON 文件。W3C File API 支持在用户选择文件后以异步方式读取文本，且不允许页面静默读取任意本地文件。来源：[W3C File API](https://www.w3.org/TR/FileAPI/)。

### 2.3 无障碍

实现目标为 WCAG 2.2 AA 可测试子集：

- 页面语义、关系与阅读顺序可以被程序识别，图形同时提供文本或表格等价物。
- 颜色不是唯一的信息通道；状态同时使用文本、符号、线型或标签。
- 普通文本对比度不低于 4.5:1。
- 320 CSS px 宽度下，除本质上需要二维浏览的图谱或表格外，不产生双向页面滚动。
- 全部功能可键盘操作，并有清晰可见的焦点。
- 标签页使用 `tablist`、`tab`、`tabpanel` 语义，支持左右方向键、Home、End、Enter 和 Space。
- 数据变化和装载错误通过 `aria-live` 状态区域通知。
- 尊重 `prefers-reduced-motion`。

依据：

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- [WAI-ARIA APG Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)
- [WAI Complex Images](https://www.w3.org/WAI/tutorials/images/complex/)

### 2.4 安全与隐私

阶段 JSON 可能包含学习者信息、研究摘录和模型判断，因此页面默认：

- 不发出网络请求，不使用遥测，不加载第三方资源。
- 不使用 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`、`eval` 或 `Function` 处理输入数据。
- 输入值只通过 `textContent`、属性白名单和 DOM/SVG 节点创建 API 渲染。
- JSON 嵌入 HTML 前至少转义 `<`、U+2028 和 U+2029，防止数据提前闭合脚本元素。
- 使用 CSP 元信息禁止网络、对象、框架、表单提交和动态代码执行，只允许当前单文件所需的内联样式与脚本。
- 页面级交互只保留在内存中；只有用户明确点击导出时才生成本地文件。
- 原始 JSON 中的敏感字段不自动复制到交互草稿；草稿只包含阶段、运行、动作类型、目标标识和用户明确输入的值。

`innerHTML` 等字符串到 DOM 的注入点属于需要约束的注入汇点。依据：[W3C Trusted Types](https://www.w3.org/TR/trusted-types/) 和 [Content Security Policy Level 3](https://www.w3.org/TR/CSP/)。

## 3. 架构决策

### 3.1 权威性

```text
阶段输入
   │
   ▼
阶段 Skill ─────► 规范 JSON 移交信封 ─────► 下游 Skill / 门禁
                     │
                     │ 单向派生
                     ▼
                单文件 HTML 视图
                     │
                     └────► 可选交互草稿 JSON
                                  │
                                  └────► 重新提交给阶段 Skill 后才可成为证据
```

规则：

- JSON 是唯一权威工件。
- HTML 不得反写或覆盖 JSON。
- HTML 中的筛选、展开和聚焦只是显示状态。
- HTML 中填写的确认、回答、路线偏好或复核意见只是草稿。
- 草稿被重新提交给相应 Skill、通过输入校验并写入新一版规范 JSON 后，才具有业务效力。
- HTML 生成失败不得改变原阶段门禁结果；失败必须在移交信封中显式记录。

### 3.2 共同实现

七个 Skill 各自携带一份 `assets/stage-report.html`，保证 Skill 被单独复制时仍能工作。七份模板保持字节一致，通过 `stage_id` 选择阶段专属渲染器。

每个 Skill 同时携带一份 `references/html-visualization-contract.md`，说明：

- 输入和输出约束。
- 安全嵌入步骤。
- 阶段视图字段映射。
- 交互草稿边界。
- 验证与失败处理。

共同移交信封升级到 `1.1.0`，新增必填 `presentation_artifact`。该字段记录派生 HTML 的生成与验证事实，但不改变 `positive_artifact` 的含义。

### 3.3 `presentation_artifact` 契约

```json
{
  "format": "html",
  "status": "generated",
  "path": "relative/or/absolute/report.html",
  "authority": "derived_non_authoritative",
  "source": {
    "stage_id": "S3",
    "run_id": "run-123",
    "envelope_schema_version": "1.1.0",
    "artifact_id": "ccg-123",
    "artifact_schema_version": "1.1.0"
  },
  "interaction_mode": "draft_export_only",
  "generated_at": "2026-07-27T10:00:00Z",
  "validation": {
    "html_parse": "pass",
    "accessibility_smoke": "pass",
    "interaction_smoke": "pass"
  },
  "reason": null
}
```

约束：

- `status` 为 `generated`、`failed` 或 `not_requested`。
- `generated` 时 `path`、`generated_at` 必须非空。
- `failed` 时 `reason` 必须非空，`path` 必须为 `null`。
- `not_requested` 仅允许调用方明确声明不需要 HTML 时使用。
- 即使阶段状态为 `blocked` 或 `needs_confirmation`，也应生成诊断型 HTML；此时 `source.artifact_id` 和工件 Schema 版本可以为 `null`。
- 验证状态为 `pass`、`fail` 或 `not_run`。不得把未运行写成通过。

## 4. 七阶段视图与交互矩阵

| 阶段 | 核心任务 | 默认可视化 | 关键交互 | 草稿导出 |
|---|---|---|---|---|
| S1 目标成功契约 | 校准“学会”的可观察证据 | 目标场景摘要、能力卡、终局测评与通过规则、范围/排除项对照、确认状态 | 按已确认/待确认筛选，展开能力与证据，定位开放问题 | `goal_contract_confirmation_draft` |
| S2 领域证据地形 | 展示研究范围、主张和证据强弱 | 来源类别覆盖矩阵、研究轮次时间线、主张—证据台账、共识/分歧双栏、证据缺口 | 按来源、地区、日期、主张状态过滤；从主张追到来源；缺口下钻 | `evidence_review_draft` |
| S3 能力—概念图谱 | 展示大纲、学习单元、知识点和边关系 | 能力→子能力→学习单元树、单元—节点映射、先修/解释/支持边图、测评与掌握阈值 | 搜索节点，切换硬/软边，选择单元高亮关联知识点，查看邻接表和追溯 | `graph_review_draft` |
| S4 学习者前沿诊断 | 定位已掌握、学习中、受阻与待复测节点 | 节点状态热图、最近学习前沿、证据时间线、正确性×置信度矩阵、误概念与缺口卡片 | 按状态和证据有效性过滤；选择节点查看提示依赖、迁移与证据；可用时比较模型版本 | `diagnosis_review_draft` |
| S5 学习与会话计划 | 把最小连通子图编排为可执行路径 | 阶段路线图、会话时间线、测评计划、复习锚点、风险与备选路线分支 | 聚焦会话/节点，查看时长与退出标准，本地预览备选路线，不改规范计划 | `plan_confirmation_draft` |
| S6 教学交互 | 展示当前节点的教学内容并记录待回传回答 | 会话目标、解释与正反例、活动步骤、提示阶梯、交互事件时间线、候选掌握证据 | 逐级揭示提示，输入回答草稿，对照反馈规则，查看支架渐隐状态 | `interaction_event_draft` |
| S7 掌握验证与重规划 | 解释掌握结论、模型更新和下一路由 | 多维掌握条形图、证据依据、学习者模型前后差异、归因与路由流程、复测安排 | 按节点/判定过滤，展开维度证据，比较版本，查看路由理由与适用限制 | `mastery_review_draft` |

### 4.1 S1 详细要求

- 首屏明确目标问题、目标场景和状态。
- 能力卡显示能力名称、可观察行为、成功证据和对应终局测评。
- 通过规则使用文本、数值和状态标签，不只用颜色。
- 范围与排除项并排展示；窄屏时顺序堆叠。
- 确认草稿不能直接把 `confirmation.confirmed` 改成 `true`。

### 4.2 S2 详细要求

- 来源覆盖按所需类别和已覆盖类别展示，不以来源数量代替类别覆盖。
- 主张必须能追到来源标识；来源链接仅显示为文本，不由页面主动联网打开。
- 共识、分歧、开放问题和推断使用不同文字标签。
- 证据缺口按关键性、影响和下一步研究动作展开。

### 4.3 S3 详细要求

- 大纲视图以三层能力结构为主导航。
- 学习单元不是原子知识点的容器替代物；页面必须同时展示 `learning_units`、`nodes` 和 `unit_node_mappings`。
- 图谱边至少区分硬先修、软先修、解释和支持关系。
- 选择学习单元时同时高亮其目标能力、知识点、测评题和掌握阈值。
- SVG 或 Canvas 图形必须有邻接表或关系表等价视图。
- 图形负责探索，表格负责精确读取和无障碍访问。

### 4.4 S4 详细要求

- 节点状态至少区分已掌握、学习中、受阻、未知和待复测。
- 正确性与置信度同时呈现，避免把“答对一次”误判为稳定掌握。
- 证据视图显示来源会话、行为、提示层级、迁移表现和有效期。
- 对缺失或过期证据显式标记，不补造置信度。

### 4.5 S5 详细要求

- 路线图以学习节点为原子顺序，学习单元只作可读分组。
- 会话卡显示目标节点、进入条件、通关标准、时间预算和复习锚点。
- 备选路线预览只能形成草稿，不得直接重新排序规范计划。
- 强制确认状态必须在页首和导出动作附近重复提示。

### 4.6 S6 详细要求

- 内容按“目标 → 解释 → 正反例 → 活动 → 提示 → 反馈 → 收束”组织。
- 提示逐级揭示，默认不一次性显示完整答案。
- 本地输入不得自动写入 `interaction_events`。
- 导出的交互草稿包含提示使用、回答和自评，但必须由 S6 重新处理后才能成为已观察事件。
- 候选掌握证据必须标记为候选，不能越权形成 S7 掌握结论。

### 4.7 S7 详细要求

- 掌握维度使用可比较的条形图和数值/文字说明，不使用难以精确比较的雷达图作为唯一表达。
- 每个判定都能展开看到证据、阈值、反证、置信度和适用限制。
- 模型更新用字段级前后对照呈现。
- 路由图展示继续、复测、补救、重规划或完成的理由。
- 页面不得把“建议路线”显示为已经执行。

## 5. 共同交互要求

### 5.1 标签页

固定标签为：

- 总览
- 阶段详情
- 证据与追溯
- 质量与门禁
- 原始 JSON

标签可点击，也可通过键盘切换。当前标签具有 `aria-selected="true"`，非当前面板隐藏但不删除数据。

### 5.2 搜索、筛选与详情

- 搜索在当前阶段的标题、标识、描述和引用字段中匹配。
- 筛选只影响显示结果。
- 页面显示“当前显示数 / 总数”。
- 清除筛选后恢复完整集合。
- 选择一个实体时在详情区域显示其所有关键字段和追溯关系。
- 空数组、未知值和未提供字段使用明确占位文案，不用伪造默认值。

### 5.3 原始 JSON

- 默认折叠，用户主动打开后显示格式化 JSON。
- 提供复制按钮；失败时给出可见错误。
- 不提供“保存回原文件”能力。

### 5.4 草稿导出

导出文件必须包含：

```json
{
  "draft_schema_version": "1.0.0",
  "authority": "unsubmitted_user_draft",
  "stage_id": "S6",
  "run_id": "run-123",
  "action_type": "interaction_event_draft",
  "created_at": "2026-07-27T10:30:00Z",
  "payload": {}
}
```

导出前提示“该文件尚未成为规范学习证据”。导出使用本地 `Blob` 与 `download`，完成后撤销对象 URL。

## 6. 生成流程

1. Skill 先完成输入校验、阶段处理和 JSON Schema 校验。
2. 形成共同移交信封，但暂不最终宣称 HTML 验证结果。
3. 复制自身 `assets/stage-report.html` 到约定输出路径。
4. 将移交信封 JSON 序列化，并转义 `<`、U+2028、U+2029。
5. 只替换模板中唯一的 `stage-data` 数据块，不修改程序脚本。
6. 对最终 HTML 执行解析、静态安全与交互冒烟验证。
7. 回填 `presentation_artifact` 的路径、时间和真实验证结果。
8. 再次校验最终移交信封。

输出文件建议命名：

```text
<run_id>-<stage_id>-report.html
```

若调用方未提供输出目录，Skill 应在当前任务允许写入的工件目录中生成；若当前任务是纯聊天且未授权写文件，则使用 `not_requested` 并在结果中说明如何生成，不能声称已生成文件。

## 7. 失败与门禁处理

| 场景 | JSON 结果 | HTML 结果 |
|---|---|---|
| 阶段成功 | 正常 `positive_artifact` | 生成完整阶段页面 |
| 需要确认 | 状态为 `needs_confirmation` | 生成确认型页面，可导出确认草稿 |
| 输入阻断 | 状态为 `blocked`，无正向工件 | 生成诊断型页面，展示缺口与路由 |
| HTML 生成失败 | 阶段 JSON 仍按原规则有效 | `presentation_artifact.status="failed"`，记录原因 |
| HTML 未被请求 | 阶段 JSON 仍按原规则有效 | `presentation_artifact.status="not_requested"` |
| HTML 交互冒烟未运行 | 不影响阶段门禁 | 验证字段为 `not_run`，不得写 `pass` |

HTML 失败不是阶段业务失败；但当调用明确要求 HTML 时，整体任务不能被报告为完全完成。

## 8. 验收标准

### 8.1 契约

- 七份共同移交信封 Schema 字节一致，版本为 `1.1.0`。
- `presentation_artifact` 为必填字段，条件约束可被 JSON Schema 验证。
- 旧 `1.0.0` 工件可被识别为旧版本，但不能伪装成 `1.1.0`。
- 七个 Skill 的输出说明均明确 JSON 权威性、HTML 派生性和草稿边界。

### 8.2 页面

- 七个 Skill 都包含可独立复制的单文件模板。
- 七份模板字节一致。
- 在不联网的情况下可直接用浏览器打开。
- S1—S7 分别命中阶段专属视图，不退化为同一组通用卡片。
- 成功、待确认和阻断信封都能渲染。
- JSON 文件选择、拖放、搜索、筛选、标签切换、详情查看和草稿导出可用。
- 页面中不存在输入数据到 `innerHTML` 等危险汇点的路径。
- 页面不包含远程 URL 依赖或网络请求代码。

### 8.3 无障碍

- 关键图形有可读文字或表格等价物。
- 颜色之外有文字、符号或线型区分。
- 标签页可用鼠标和键盘切换。
- 全部按钮、输入框和可选实体可聚焦。
- 焦点轮廓可见。
- 320 px 宽度下主体信息可重排。
- 减少动态效果偏好生效。

### 8.4 验证证据

- JSON Schema 校验通过。
- OpenSpec 严格校验通过。
- HTML 解析通过。
- 静态安全扫描通过。
- 至少使用一个成功、一个待确认和一个阻断样例执行浏览器交互冒烟。
- 七个阶段均执行阶段路由冒烟，确认专属标题和关键区域出现。
- 未执行的真实账户、生产环境或辅助技术人工测试必须显式列为未运行。

## 9. 非目标

- 不建设在线学习平台或发布托管站点。
- 不在 HTML 内复制阶段业务逻辑、门禁算法或掌握判定算法。
- 不把 HTML 作为下游 Skill 输入的优先格式。

## 10. 需要创建 Spec 的评估

需要创建新的 OpenSpec change，原因如下：
