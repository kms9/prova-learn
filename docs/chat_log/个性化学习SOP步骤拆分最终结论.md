# 个性化学习 SOP 步骤拆分最终结论

> 原七步结构的结论来源：[how_to_learn.md](./how_to_learn.md) 的流程分析、[模型评估记录.md](./模型评估记录.md)中的两轮交叉验证，以及 `gclaude` 对当时最终文档的独立复核。S1–S2 的强制联网与 STORM 式调研条款是后续补充，依据本次需求及 STORM 官方方法资料，未包含在该轮 `gclaude` 复核中。  
> 目标：先确定稳定的顶层 SOP，后续再把它转化为可编排、可评估的 Skill。

## 1. 最终结论

标准流程拆分为 **7 个顶层步骤**：

1. 目标与成功契约；
2. 领域取证与认知全景；
3. 能力—概念图建模；
4. 学习者诊断与学习前沿；
5. 路径与会话规划；
6. 内容生产与教学交互；
7. 掌握验证、模型更新与重规划。

主流程不是一次性瀑布，而是三个相连的循环：

```text
S1 目标与成功契约
 ↓
S2 领域取证与认知全景 ↔ S3 能力—概念图建模
                              ↓
S4 学习者诊断与学习前沿 → S5 路径与会话规划
                              ↓
                        S6 内容生产与教学交互
                              ↕
                    S7 掌握验证、更新与重规划
                      ├─ 下一学习节点 → S6
                      ├─ 路径需调整   → S5
                      ├─ 诊断有误     → S4
                      ├─ 图谱/证据有误→ S2/S3
                      └─ 目标已改变   → S1
```

这里的“7 步”是运行阶段数，不代表未来必须机械实现成恰好 7 个独立程序。拆 Skill 时应优先保留阶段契约和决策门，再决定哪些阶段独立封装、哪些能力作为共享工具。特别是 S7 在顶层 SOP 中保持一步，但实现时建议拆成 `mastery-verifier` 和 `learner-model-replanner` 两个物理 Skill。

### 1.1 `gclaude` 对原七步结构的独立复核结论

`gclaude` 在 S1–S2 强制研究条款补充前，只读检查原始讨论、模型评估记录和当时的结论文档后，返回：

| 项目 | 结果 |
|---|---|
| 判定 | `pass_with_changes` |
| 推荐顶层步骤数 | 7 |
| 置信度 | `0.78` |
| 实际模型证据 | `modelUsage` 主要为 `glm-5.2`，另有少量 `glm-5.1` |

复核确认 7 步的核心结构成立，尤其确认：

- S2 的证据门和 S3 的模型门具有不同量规和失败归因，应在标准 SOP 中分开；
- S1–S7 均已包含信息收集、确认、加工、正向工件、质量评估、通过和返工；
- S1–S6 主要检查“工件做对没有”，S7 检查“学习者学会没有”，两类评估没有混为一谈；
- 5 步档只有在“合并执行但保留全部质量门”时才安全；
- 原文 12 项是能力组件目录，不是 12 个顶层时序步骤。

复核同时指出：当前文档已经足以确定顶层步骤，但**尚未达到可直接实现 Skill 的规格完整度**。正式 Skill 化之前仍需补齐工件 JSON Schema、学习者模型持久化、确定性路由、量规阈值和确认状态机。本结论因此是“步骤设计通过、实现规格有待补齐”，不是“Skill 已可直接编码”。

## 2. 每一步统一使用的双段结构

每个步骤都必须有两部分，不能只有内容生成，也不能只有评价意见。

### A. 正向输出流程

```text
输入契约校验
→ 需求信息与缺口收集
→ 确认交互
→ 事实、证据或学习行为信息收集
→ 分析加工
→ 生成具名正向输出工件
```

“需求信息收集”和“任务数据收集”不是重复：前者明确本步要解决什么、缺什么、按什么约束做；确认后，后者才真正采集完成任务需要的领域证据、结构建模信息、学习行为、规划上下文或掌握证据。

S1、S2 允许在正式确认前进行一次有边界的联网预检，用来发现术语歧义、相邻岗位、来源可用性和研究范围分歧；预检结果只是待确认线索，不是已经成立的目标或领域事实。用户确认研究口径后，仍须执行完整取证，不能用预检代替正式研究。

每一步必须显式记录输入契约校验结果，不能只在统一模板中声明但在阶段契约中省略。至少检查：工件类型、Schema 版本、必填字段、来源阶段、追溯信息和质量门状态。

### B. 输出质量评估流程

```text
读取本步工件
→ 按本步专属量规逐项检查
→ 给出证据、分数或通过状态
→ 判断通过、局部返工或上游返工
→ 通过后才允许移交下一步
```

统一内核只规定流程形状，不使用一个万能量规评价所有工件。来源清单、概念图、诊断快照、教学内容和掌握证据必须使用不同的质量标准。

每项量规在 Skill 规格中必须进一步操作化为：

```text
维度
→ 证据
→ 评分或布尔结果
→ 通过阈值
→ pass / revise_here / return_upstream
→ route_to
```

## 3. 确认交互的三种强度

为了既保留用户控制权，又避免每一步都打断用户，确认分为三种：

| 类型 | 含义 | 默认使用位置 |
|---|---|---|
| 强制确认 | 未确认不得进入下一阶段 | S1 目标契约、S5 路径与时间承诺 |
| 条件确认 | 存在分歧、高风险假设或多个可行方案时才阻塞 | S2、S3、S4、S7 |
| 告知后继续 | 展示结果和默认选择；用户可纠正，否则继续 | S6 的节点推进等低风险动作 |

“用户确认”确认的是目标、约束、重要假设和行动选择，不要求用户替系统确认其并不具备判断能力的专业事实。

确认交互必须实现为可记录的状态机：

```text
pending
├─ mandatory → confirmed | rejected
├─ conditional
│  ├─ 未触发升级条件 → acknowledged
│  └─ 触发高风险/重大分歧/多方案条件 → mandatory
└─ inform → acknowledged | corrected
```

确认记录至少包含 `mode`、`trigger`、`question`、`response`、`status`、`confirmed_at` 和 `assumptions_changed`。S2 遇到前沿、高风险或强争议主题时，必须从条件确认升级为强制确认。

## 4. 七个步骤的完整契约

### S1–S2 的强制外部研究原则

S1 和 S2 共同构成“目标校准—领域研究”阶段。该阶段**禁止只依据模型参数中的既有知识直接生成目标契约、能力要求或认知全景**。模型自身理解只能用于提出待验证假设、研究视角、问题和检索词，不能充当外部证据。

每次冷启动、目标实质变化或关键证据过期时，必须重新执行联网检索。若网络或检索器不可用，应把状态记录为 `research_blocked`，不得把模型记忆包装成“已完成调研”，也不得通过 G1/G2。若个别资料缺失，则记录 `evidence_gap`、重要性和对当前决策门的影响；关键缺口阻塞相应决策门，非关键缺口可以在限制结论范围和降低置信度后继续。用户可以选择等待、缩小范围或提供可验证资料，但不能通过确认豁免证据门。

最低来源覆盖矩阵如下；“包括但不限于”表示可以扩展来源类型，但不能静默删除这些类别：

| 来源类别 | 强制研究内容 | 在 SOP 中的用途 | 使用边界 |
|---|---|---|---|
| Wikipedia、维基百科及专业百科 | 术语、别名、历史、主要分支、相关条目和参考文献线索 | 建立检索词表、发现领域结构和相邻概念 | 只作为全景入口和线索，不单独支撑高风险或争议结论 |
| 官方、学术与规范性来源 | 标准、法规、官方文档、教材、综述、论文、专业组织能力框架 | 支撑领域事实、规范、方法和争议判断 | 关键规范性结论优先追溯一手来源 |
| 实践与案例来源 | 真实案例、开源项目、技术报告、行业实践、失败复盘 | 识别工作流程、边界条件和常见问题 | 个案经验不得伪装成普遍规律 |
| 招聘与职业来源 | 当前 JD、职业标准、职级说明、认证要求、作品集要求 | 识别真实任务、常见技能、工具、资历和协作要求 | JD 是市场样本，不是科学事实；必须区分任务、可学习能力、背景筛选和组织偏好 |
| 面试与选拔来源 | 官方面试说明、公开面经、题库、实操题、take-home、认证样题 | 发现雇主或专业共同体如何观察能力，并为后续评估题提供线索 | 不把记忆题库等同于能力标准；记录题目来源、时效、岗位层级和可能失真 |
| 反方、争议与前沿来源 | 竞争范式、批评、失败证据、最新进展和未决问题 | 防止把单一流派写成共识，暴露知识边界 | 新颖性和流行度不能替代证据质量 |

对每一类来源都必须记录 `covered / not_applicable / gap`，并附 `criticality` 与 `gate_effect`。只有确实不适用时才能标为 `not_applicable`，并写明理由；找不到资料应标为 `gap`，不能写成“不适用”。默认至少抽取多个相互独立的来源：招聘研究至少覆盖 3 个当前岗位样本和 2 个不同组织；面试研究至少覆盖 2 组独立样本。极窄领域无法达到默认样本量时，保留缺口并降低置信度，不得补造样本；若缺口会影响目标定义、核心能力或关键事实，则相应决策门不通过。

本文所称“STORM 式调研”采用 STORM 的研究内核：从相邻主题发现多种视角，由不同视角提出问题，检索互联网资料，让回答严格落在检索来源上并继续追问，最后策展为可追溯的结构化全景；不要求 S2 额外生成一篇 Wikipedia 风格长文。方法依据参见 [Stanford OVAL STORM 官方仓库](https://github.com/stanford-oval/storm)与 [NAACL 2024 论文](https://aclanthology.org/2024.naacl-long.347/)。

### S1. 目标与成功契约

#### A. 正向输出

**目的**：把模糊的“我想学某领域”与初步外部现实校准，转化成可以观察、验证和约束范围的目标。

**输入**：用户的学习诉求、目标问题、使用场景和已有材料。

**输入契约校验**：确认至少存在一个目标问题或使用场景；记录缺失的约束、材料来源和待确认假设；检查联网检索能力、检索日期、目标地区/语言和资料可访问性。冷启动允许输入不完整，但不得把未确认推断或模型既有知识写成已确认目标。

**需求信息与缺口收集**：

- 最终要解决什么真实问题；
- 谁在什么情境下使用这项能力；
- 目标是学术理解、工作胜任、求职面试、认证考试、项目交付还是其他用途；
- 若面向职业，目标岗位名称、相邻岗位、地区、行业、组织类型和期望职级；
- 期望达到解释、应用、诊断、评价还是创造层级；
- 时间预算、截止时间、资源和形式限制；
- 已知排除项和不可接受结果；
- 什么证据能让双方同意“已经达到目标”。

**强制联网预检**：在正式确认前执行轻量研究，至少查询 Wikipedia/专业百科中的术语与相邻概念、相关岗位与当前 JD、相关面试或实操选拔样本；同时查找可用于 S2 的权威来源入口。预检用于校正用户表述，例如识别岗位名称不统一、目标层级不清、实际工作任务与想象不一致等问题。即使模型“知道”该领域，也不得跳过该步骤。

**确认交互**：把联网预检发现的术语校正、相邻目标、市场任务和评估方式连同来源展示给用户；强制确认目标能力、成功证据、范围、地区/行业/职级口径、时间约束和排除项。模糊点未消除前不进入 S2。

**任务场景信息收集与加工**：结合用户材料与外部预检，收集目标任务的正例、反例和典型使用场景；将 JD 中的工作任务、可学习能力、背景筛选条件和组织偏好分开；参考真实面试/实操形式，把目标反推为可观察的能力陈述和初始验收任务，但不得直接照抄题库或把“通过面试”等同于“掌握领域”。

**正向输出工件：`goal_success_contract`**

- 目标问题和目标使用场景；
- 目标术语、相邻领域或岗位的校正记录；
- 可观察的能力阶梯；
- 最终验收任务与通过标准；
- 初步市场任务、能力/技能要求和面试/实操评估模式；
- 领域初始假设和排除项；
- 时间、资源、输出形式约束；
- `external_research_seed`：检索日期、查询词、种子来源、来源类别覆盖状态、适用地区/语言、证据缺口；
- 未决问题和已确认项。

#### B. 输出质量评估

**专属量规**：目标可观察性、成功标准可判定性、场景真实性、外部现实校准度、强制来源类别覆盖度、边界清晰度、约束完整性、目标与验收任务一致性。

**通过条件**：联网预检已实际执行并留下可访问来源和查询记录；Wikipedia/百科、招聘、面试/实操三类种子来源均为 `covered`，或对 `not_applicable/gap` 给出可审计理由、重要性和门禁影响，且不存在会妨碍目标确认的关键缺口；每项核心能力至少有一个可观察证据；验收任务能区分“记住信息”和“能解决问题”；用户完成强制确认。

**返工**：目标或成功标准不清时留在 S1；岗位/领域称谓与外部证据不一致时补充预检并重新确认；网络研究未执行或只有模型总结时不得通过 G1；用户改变根本目标时，无论流程进行到哪里都返回 S1。

### S2. 领域取证与认知全景

#### A. 正向输出

**目的**：建立可追溯的领域事实基础，识别共识、分歧、核心思维模型、边界和未决问题。

**输入**：`goal_success_contract` 和用户提供的资料。

**输入契约校验**：检查目标、成功证据、范围和排除项是否已通过 G1；用户资料必须保留来源标识，无法验证的材料不得默认视为领域事实。

**需求信息与缺口收集**：基于 S1 的 `external_research_seed` 确定需要覆盖的子领域、STORM 研究视角、证据类型、目标地区与岗位层级、来源语言、时间范围、严谨度和资料可访问性；识别哪些结论必须有原始来源支持，以及 Wikipedia、招聘和面试样本中仍缺哪些类别。

**确认交互**：先展示研究视角、核心问题、必查来源类别和预期深度；对争议范围、来源限制、地区/岗位口径、研究深度和成本做条件确认。高风险或前沿主题必须确认取证标准。

**领域证据信息收集与加工**：强制执行联网检索和 STORM 式多视角调研，审阅百科、教材、论文、标准、权威文档、案例、招聘、职业标准、面试与实操评估等资料；记录来源；区分共识、流派分歧、经验做法、市场信号和推断；形成认知全景。用户资料与本地语料可以补充网络证据，但不能替代强制联网检索。

**S2 内部强制执行序列**：

```text
从 S1 目标框定主题、地区、岗位/应用场景和时间边界
→ 从百科条目、相邻主题和种子资料发现研究视角
→ 为每个视角提出核心问题、反例问题和后续追问
→ 生成并执行可追溯的多轮网络查询
→ 由“视角提问者”向“检索来源约束的领域回答者”开展模拟对话
→ 新发现或冲突触发后续查询，不允许只做一次搜索
→ 建立来源台账、结论—证据映射和岗位/面试能力矩阵
→ 区分 supported / partially_supported / unsupported
→ 审计来源类别、观点、地区、时效和反方覆盖
→ 形成认知全景；重大范围变化时回到条件确认
```

默认研究视角至少覆盖以下六类：术语与历史、理论与标准、实践者与真实任务、招聘者与市场能力、面试官/评估者与可观察证据、批评者与前沿争议。可以增加学习者、管理者、安全/伦理、地区文化等视角。这里的“专家”是由不同视角驱动、且回答受检索来源约束的研究角色，不得伪装成已咨询真实人类专家；研究级或高风险场景仍需按规则增加真实专家复核。

**招聘与面试信息的专门加工规则**：

- 对 JD 去重并记录组织、地区、职级、发布日期或抓取日期，避免把同一聚合内容当成多个独立样本；
- 把“工作任务、工具/知识技能、可观察能力、学历/年限/证书、软性偏好”分别编码；
- 统计重复出现的要求，同时保留少数但高风险或高价值的要求，不只按词频决策；
- 对面试题标注题型、目标能力、认知层级、参考答案可信度、是否来自官方/真实面经/培训题库；
- 将面试题和 take-home 视为后续诊断与验收设计的候选证据，不直接复制为教学答案，也不把押题成功当作迁移能力；
- 当招聘信号与权威标准冲突时并列呈现，分别标为“市场要求”和“规范/事实依据”，不得强行合并。

**正向输出工件：`domain_evidence_landscape`**

- 范围声明和术语表；
- `research_run_manifest`：研究时间、联网状态、范围、视角、问题、查询和执行状态；
- 来源台账及证据映射，含 URL、标题、发布者、来源类别、发布时间/抓取时间、地区、可靠性和适用边界；
- 核心问题与思维模型；
- Wikipedia/百科领域导航与待追溯的一手参考线索；
- JD 样本及“任务—能力—技能—工具—背景条件”矩阵；
- 面试题、实操题、认证样题及其“题型—能力—层级—可信度”矩阵；
- 专家共识、主要分歧及双方强论据；
- 典型问题、异常情况与未决问题；
- `claims` 及其 `supported / partially_supported / unsupported` 状态；
- 证据缺口、置信度和待验证假设。

#### B. 输出质量评估

**专属量规**：实际联网执行、强制来源类别覆盖、来源可靠性、结论可追溯性、关键主题覆盖率、STORM 视角与问题多样性、后续追问深度、岗位/面试样本代表性、时效与地区适配性、事实/市场信号/推断分离、证据缺口透明度。

**通过条件**：`research_run_manifest` 证明网络查询和多视角研究已实际执行；最低来源覆盖矩阵均有状态且默认样本量达标，未达标项被标为缺口、限制相应结论且不影响核心领域判断；关键结论可追溯到来源，重要结论原则上有多个独立来源交叉验证，单一权威一手来源足够时记录例外理由；重要争议没有被单边意见伪装成共识；招聘要求没有被误写成普适知识标准；面试题没有被误写成能力本体；证据缺口被显式标记。

**返工**：未执行联网查询、只返回模型常识、来源类别缺失、来源不足、查询过浅或冲突未解释时在 S2 补证；网络不可用时状态为阻塞而不是通过；S3 建图发现证据空白时返回 S2 局部补充，而不是推倒全部结果。

### S3. 能力—概念图建模

#### A. 正向输出

**目的**：把目标问题和领域证据转成“能力—问题—概念—先修关系—掌握证据”的可计算结构。

**输入**：`goal_success_contract`、`domain_evidence_landscape`。

**输入契约校验**：检查两个上游工件已分别通过 G1、G2，且目标、范围和来源标识可以互相追溯；发现证据缺口时返回 S2，不在 S3 内隐式补造领域事实。

**需求信息与缺口收集**：确定建模粒度、目标能力优先级、三层能力大纲的适用深度、学习单元—知识点关联、
概念类型、硬/软先修边规则和需要支持的诊断深度。三层是“能力领域 → 子能力/问题族 → 可测评学习单元”
的语义模板；窄目标可省略中间层，但必须记录理由，不得为凑层级制造空节点。

**确认交互**：向用户展示目标能力主干、学习单元粒度、核心单元—知识点关联和关键先修边界；对优先级、
明显遗漏或多种会实质改变诊断/路径的建模方案做条件确认。

**结构建模信息收集与加工**：只基于 S1 目标和 S2 已审计证据，从目标能力反推所需判断和任务；组织
目标能力、子能力和可测评学习单元；拆解原子概念、程序、策略、表征与元认知节点；建立学习单元—知识点
多对多关联；再独立建立先修关系。层级父子关系只表示组成，展示顺序不得自动成为先修边。为每个节点绑定
可解决问题、常见误解和评估题。

**正向输出工件：`capability_concept_graph`**

- 目标能力、子能力和典型任务；
- 可测评学习单元及其父级、退出能力、目标/来源追溯和范围角色；
- 概念、程序、策略、表征和元认知节点；
- 学习单元—知识点的 `core / supporting / extension` 多对多关联及理由；
- 硬/软先修关系及其理由；
- 每节点的能力陈述和常见误解；
- 解释、应用、诊断、迁移等评估题；
- 掌握门槛和补救入口；
- 节点到来源、目标和验收任务的追溯关系。

`capability_concept_graph` 是唯一机器可执行结构真值源。三层大纲是该工件中的层级视图，不另建与图谱
并行维护的 `learning_architecture` 工件。学习单元、知识点和关联使用稳定 ID；语义实质变化必须产生
新工件版本并显式记录下游失效范围。

#### B. 输出质量评估

**专属量规**：层级无环性、学习单元核心覆盖率、目标必需知识点无孤儿、关联引用完整性、重复知识点检查、
硬先修子图无环性、先修边可解释性、目标覆盖率、节点粒度一致性、能力与概念区分度、评估题有效性、
全链路可追溯性。

**通过条件**：每个学习单元至少关联一个核心知识点；每个目标必需知识点至少被一个学习单元覆盖；不存在
悬空关联或语义重复的核心节点；每个目标能力都能追溯到必要节点；每个关键节点都有可观察能力和评估证据；
不存在无理由的关键先修边或无法解释的孤立节点。

**返工**：层级、粒度、关联、覆盖、重复或先修结构问题在 S3 修正；事实依据不足返回 S2；目标本身不一致
返回 S1。S5 发现结构或版本不可靠时返回 S3，不在路径规划中修补。S2 与 S3 必须允许多轮局部迭代。

### S4. 学习者诊断与学习前沿

#### A. 正向输出

**目的**：用行为证据确定学习者已经能独立解决什么、缺口在哪里，以及从哪个节点开始最合适。

**输入**：`goal_success_contract`、`capability_concept_graph`、已有学习记录。

**输入契约校验**：检查目标契约与图谱已通过 G1、G3，关键节点具有可执行的诊断项；验证已有学习记录的身份、时间、来源和有效期，过期证据只能作为诊断线索。

**需求信息与缺口收集**：收集学习者自述、既有作品、时间状态和可接受的诊断方式；识别尚无证据的关键节点。

**确认交互**：说明诊断范围和使用方式；展示初步结论。学习者对结论有异议时，对争议节点追加测试，不用自述直接覆盖行为证据。

**学习行为证据信息收集与加工**：沿目标和先修链使用解释、预测、反例、诊断、比较、迁移和置信度任务；记录正确性、推理过程、提示次数、耗时、置信度和错误类型；递归定位学习前沿。

**正向输出工件：`learner_snapshot`**

- 已测、已掌握、未掌握和证据不足的节点；
- 学习前沿和最近可学习节点；
- 错误类型、误概念和能力缺口；
- 提示依赖、置信度校准和迁移表现；
- 诊断证据与结论的对应关系；
- 需要复测或人工确认的项目。

#### B. 输出质量评估

**专属量规**：测量与目标对齐度、证据充分性、猜对识别、提示依赖记录、错误分类一致性、偏差控制、结论可解释性。

**通过条件**：关键结论不是由单题或纯自述决定；能区分“答对”“独立会做”和“可迁移”；学习前沿有可追溯证据。

**返工**：证据不足在 S4 补测；题目无效返回 S3 改评估项；诊断暴露图谱缺失返回 S2/S3。

### S5. 路径与会话规划

#### A. 正向输出

**目的**：从学习前沿到目标能力选择最小可行子图，并把它编排为有通关标准的学习会话。

**输入**：`learner_snapshot`、`capability_concept_graph`、`goal_success_contract`。

**输入契约校验**：检查学习者快照、图谱和目标的版本一致性及追溯关系；关键学习前沿若仍为“证据不足”，不得被当作已确定起点直接规划。

**需求信息与缺口收集**：补充可用时间、节奏、资源、交付形式、动机和任务情境；识别计划中的依赖、风险和资源缺口。

**确认交互**：强制确认路径概览、阶段目标、时间投入、优先级和第一个会话契约。用户确认的是取舍，不是每个内部算法细节。

**规划上下文信息收集与加工**：选择前沿到目标的最小连通子图；按概念类型、错误类型和认知目标匹配教学策略；编排讲解、练习、检索、交错、迁移和延迟复测；定义每节点退出标准。

**正向输出工件：`learning_and_session_plan`**

- 阶段目标和有序学习节点；
- 节点选择与排序理由；
- 每节点的教学策略、支架和撤架条件；
- 会话目标、活动、预计时间和输入材料；
- 即时、迁移和延迟测评安排；
- 复习锚点、风险和替代路线；
- 每个节点及整体路径的通关标准。

#### B. 输出质量评估

**专属量规**：目标连通性、先修正确性、路径最小性、时间可行性、策略适配性、教学与测评对齐度、认知负荷、调整空间。

**通过条件**：路径从已证实前沿连到目标；没有不可解释的冗余或跨越硬先修；首个会话可在约束内执行；用户完成强制确认。

**返工**：资源或时间不可行时在 S5 调整；诊断依据不稳返回 S4；目标发生变化返回 S1。

### S6. 内容生产与教学交互

#### A. 正向输出

**目的**：为当前学习节点生产可使用的教学内容，并通过交互帮助学习者形成可验证的理解和能力。

**输入**：`learning_and_session_plan` 当前节点、图谱节点信息、证据全景和学习者快照。

**输入契约校验**：检查当前节点属于已确认路径，硬先修已满足，内容来源可追溯，学习者快照仍在有效期内，且会话目标与节点通关标准一致。

**需求信息与缺口收集**：检查本会话目标、可用媒介、学习者当前状态、材料和例子缺口；确定本轮需要解释、示范、练习还是迁移。

**确认交互**：会话开始时确认目标和约束；节点完成时告知默认下一动作。学习者卡住、疲劳或请求改变形式时触发条件确认。

**教学内容与交互证据信息收集及加工**：从已审计证据中选择内容；生成解释、表征、正反例、渐进练习和反馈；按回答动态调整提示，逐步撤掉支架；完整记录交互证据。

**正向输出工件：`session_package_and_trace`**

- 会话目标和成功条件；
- 准确、分层的解释与多种表征；
- 正例、反例、边界案例和常见误解；
- 练习、提问、项目或模拟任务；
- 提示阶梯、反馈规则和撤架策略；
- 学习者回答、提示使用和修正轨迹；
- 节点结束时的候选掌握证据。

#### B. 输出质量评估

**专属量规**：内容正确性与可追溯性、对目标和学习者的适配、认知层级、例子代表性、支架质量、答案泄露控制、学习者主动性、交付可用性。

**通过条件**：内容无关键事实错误；活动能产生后续可判定的学习证据；难度处于当前可学习范围；提示没有代替学习者完成关键推理。

**返工**：内容错误或形式不合适在 S6 重生成；连续卡住且不是内容质量问题时返回 S5 调策略，必要时返回 S4 重诊断。

### S7. 掌握验证、模型更新与重规划

#### A. 正向输出

**目的**：判断学习者是否真正掌握并能迁移，把新证据写入学习者模型，然后决定下一步。

**输入**：`session_package_and_trace`、历史 `learner_snapshot`、当前计划和节点掌握规则。

**输入契约校验**：检查会话记录完整、掌握规则在测评前已经确定、历史学习者模型版本可用，且内容质量问题没有被误当成学习者能力问题。

**需求信息与缺口收集**：识别掌握判断缺少哪类证据，检查是否需要独立作答、迁移任务、置信度复核或延迟复测。

**确认交互**：收集学习者反思；向用户说明掌握结论、证据、仍存缺口和调整理由。重大路径变更触发条件确认。

**掌握证据信息收集与加工**：综合正确性、推理质量、提示依赖、迁移、置信度和延迟保持；区分内容质量问题、教学策略问题与学习者知识缺口；更新节点状态、遗忘风险和复习队列；选择继续、补救、重规划或完成。

**正向输出工件：`mastery_and_replanning_bundle`**

- 节点级掌握证据和判定；
- 未掌握原因及其归因；
- 更新后的学习者模型；
- 继续、补救、跳过、重诊断或完成决策；
- 调整后的路径和下一会话契约；
- 检索、间隔、交错与延迟复测安排；
- 变更理由和证据追踪。

**学习者模型持久化契约**：

- 使用稳定的 `learner_id`、`model_version`、`updated_at` 和证据事件 ID；
- 将原始学习证据、推断出的掌握状态和重规划决策分层保存；
- 更新采用版本检查，避免并发会话覆盖较新的状态；
- 读取时返回模型版本、证据有效期和缺失字段，不把“无记录”等同于“未掌握”；
- 冷启动时创建“未知/证据不足”状态，路由到 S4，而不是创建全未掌握画像；
- 保留变更前后值、证据来源和决策理由，以支持回滚与审计。

#### B. 输出质量评估

**专属量规**：证据充分性、掌握规则一致性、提示影响控制、迁移与延迟证据、更新前后一致性、调整可解释性、避免单次结果过度反应。

**通过条件**：掌握结论有多维证据；学习者模型的每项关键变化都能追溯到新证据；下一动作与归因相匹配。

**确定性返工与路由表**：

| 主归因代码 | 判定条件 | `route_to` | 动作 |
|---|---|---|---|
| `EVIDENCE_INSUFFICIENT` | 缺少独立、迁移或延迟证据，无法满足预定掌握规则 | S7 | 补测或安排延迟复测，不更新为已掌握 |
| `CONTENT_QUALITY` | 内容错误、来源不可追溯、示例或题目失效 | S6 | 修复内容并使受影响证据失效 |
| `STRATEGY_OR_SEQUENCE` | 内容正确，但难度、支架、顺序或节奏不适配 | S5 | 重选策略或调整路径 |
| `DIAGNOSTIC_ERROR` | 新证据与学习前沿假设冲突，且不能由单次波动解释 | S4 | 对争议节点重新诊断 |
| `GRAPH_ERROR` | 先修边、节点粒度或评估映射错误 | S3 | 修正模型并重新计算受影响路径 |
| `SOURCE_ERROR` | 图谱错误来自来源缺失、偏差或冲突未处理 | S2 | 补证后再进入 S3 |
| `GOAL_CHANGED` | 目标、成功标准、范围或约束发生实质变化 | S1 | 重签目标与成功契约 |
| `NODE_MASTERED` | 达到预设门槛且没有待完成的必要延迟检查 | S6 | 进入下一学习节点 |
| `GOAL_ACHIEVED` | 最终验收任务和整体保持要求均通过 | 完成 | 输出最终能力证据与后续保持计划 |

存在多个归因时，按“目标 → 来源 → 图谱 → 诊断 → 路径 → 内容 → 证据”的上游优先级路由；先修复最早污染源，再重新验证下游工件。每次路由必须记录主归因、次要归因、证据和失效范围。

## 5. 七个关键决策门

| 决策门 | 必须回答的问题 | 不通过时 |
|---|---|---|
| G1 目标门 | 目标、成功证据和边界是否经过强制联网预检并得到确认？ | 留在 S1；补检索或重新确认 |
| G2 证据门 | 是否实际完成联网与 STORM 式多视角研究，且关键结论有可靠、平衡、可追溯的证据？ | 返回 S2 补检索、补视角或补证 |
| G3 模型门 | 层级、学习单元—知识点关联和先修图能否一致覆盖目标并支持诊断和评估？ | S3 修模或 S2 补证 |
| G4 诊断门 | 学习前沿是否由充分行为证据支持？ | S4 补测或 S3 改题 |
| G5 计划门 | 路径是否正确、最小、可执行并得到确认？ | S5 调整 |
| G6 交付门 | 内容是否正确、适配且能产生有效学习证据？ | S6 返工 |
| G7 掌握门 | 是否学会、应如何更新、下一步为何如此？ | 按归因路由到 S1–S7 |

## 6. 为什么其他拆分不如 7 步

### 不采用 4–5 步作为标准版

它会把目标澄清、外部取证、知识建模和学习者诊断压进一两个大步骤。发生错误时无法回答：是目标定义错、资料偏、图谱错，还是诊断题无效。它只适合已知领域、低风险、零基础用户的快速运行。

### 不采用 6 步作为标准版

不能只用一种 6 步配置代表全部可能方案。至少需要比较三个候选：

| 6 步候选 | 主要问题 | 结论 |
|---|---|---|
| 合并 S2+S3 | 把“依据是什么”和“结构是什么”合并，G2 证据门与 G3 模型门失去独立性 | 新兴、争议和高风险领域不可接受 |
| 合并 S4+S5 | 把“学习者实际缺什么”的测量与“下一步学什么”的决策合并，容易用计划假设替代诊断证据 | 仅明确零基础的低风险场景可作为快速档 |
| 合并 S6+S7 | 把内容和教学工件质量与学习效果判断放进同一步，失败时不易区分“教得不对”还是“尚未学会” | 可作为内部逐节点循环，但不适合作为标准顶层边界 |

因此，7 步并不是只比首轮“合并 S2+S3”的 6 步更好；它同时保留了诊断与规划、教学工件与学习效果之间的独立质量门。6 步可以是受约束的运行实现，但不能代替标准语义契约。

### 8 步是需要保留的竞争方案

最有竞争力的 8 步不是随意增加交接，而是把 S7 拆为：

```text
S7 掌握验证
→ S8 学习者模型更新与重规划
```

它具有真实优点：掌握验证负责把交互数据变成可信学习证据，更新与重规划负责把证据变成状态和行动，两者之间存在干净的“证据 → 决策”边界。原先用“共享证据会增加同步风险”完全否决该方案，论据过强。

本方案仍将顶层 SOP 保持为 7 步，理由是：

- 顶层 S7 表达一个完整的反馈事务：验证结果必须被原子地写入模型并产生下一动作；
- SOP 步数和物理 Skill 数已经解耦；
- 实现层可以把 S7 拆成 `mastery-verifier` 与 `learner-model-replanner`，并用版本化证据契约连接；
- 如果未来证明两个组件需要独立部署、独立人工审批或不同权限，再把顶层 SOP 升级为 8 步，不会影响 S1–S6。

“三层大纲 + 知识点关联”不构成另一个 8 步候选：它与先修图共享同一组目标、来源、节点和 G3 不变量，
应作为 S3 内部层级视图和关联表统一提交。独立拆出会制造两个结构真值源，而不是增加有独立失败归因的质量门。

9 步及以上若继续把复习调度、模型写入和路径决策分别提升为顶层步骤，才会明显产生薄契约和状态同步负担。因而结论不是“8 步必然过细”，而是“当前没有必要把实现层拆分提升为顶层运行语义”。

### 不直接采用 12 个子 Skill

原文的 12 项是能力目录，不是同一层级的时间流程。其中：

- `goal-capability-contract` 对应 S1；
- `domain-scope-discovery` 与 `expert-landscape-mapper` 服务 S2；
- `concept-graph-builder` 对应 S3；
- `learner-diagnostic` 对应 S4；
- `recursive-concept-decomposer` 同时服务 S3 和 S4；
- `learning-path-planner` 与 `instruction-strategy-router` 服务 S5；
- `learning-content-generator` 对应 S6；
- `mastery-transfer-evaluator` 与 `learner-model-updater` 服务 S7；
- `practice-scheduler` 横跨 S5 和 S7；
- `learning-quality-evaluator` 是所有阶段的横切能力。

把它们直接排成 12 步会混淆“什么时候运行”和“调用什么能力”。

## 7. 复杂度降级规则

标准契约始终保留 7 步语义；运行时可以合并执行，但不能删除对应工件的质量检查。

S1 的联网预检、S2 的联网检索、STORM 式多视角提问、最低来源覆盖矩阵和结论—证据映射属于**不可降级要求**。快速档只能减少问题数量、每个视角的追问轮数和非关键来源数量，不能切换为“仅基于模型已有知识”。网络不可用时可以暂停或缩小任务，不能以快速档名义跳过 G1/G2。

| 档位 | 适用场景 | 运行方式 |
|---|---|---|
| 快速 5 步 | 领域成熟、单一范式、目标窄、学习者明确零基础 | 合并 S2+S3；合并 S4+S5 |
| 标准 7 步 | 中等复杂度领域、有部分先验知识 | 完整运行，每步轻量质检 |
| 严谨 7 步 | 新兴/争议领域、中高级学习者、高风险输出 | 完整运行；S2↔S3 多轮；关键工件使用独立评审 |
| 研究级 7 步 | 前沿领域、专家目标、长期学习 | 严谨档基础上增加外部专家校验和纵向延迟复测 |

### S2+S3 合并规则

只有领域成熟、单一范式、来源质量均匀且任务低风险时才允许合并执行；合并后仍必须分别输出 `domain_evidence_landscape` 和 `capability_concept_graph`，并依次通过 G2、G3。

以下情况禁止合并：存在多个竞争范式、活跃专家分歧、来源可靠性差异明显、新兴领域证据快速变化，或结果会用于高风险决策。

### S4+S5 合并规则

只有同时满足以下条件才允许合并：

- 学习者明确为零基础，且没有相反的历史作品或行为证据；
- 图谱存在明确起点，不需要选拔、分班、跳级或证书认定；
- 路径接近线性，不存在多个竞争学习前沿；
- 任务低风险，错误起点可以在首轮 S6/S7 循环中低成本纠正。

以下情况禁止合并：学习者有任何先验知识但分布未知、需要自适应跳过节点、诊断影响高风险决策、存在多条可选路径，或已有证据相互冲突。禁止合并时必须先由 S4 形成独立 `learner_snapshot`，通过 G4 后才能进入 S5。

## 8. 后续转 Skill 时的建议边界

建议保留一个总控编排器、七个阶段契约，并把 S7 实现为两个物理 Skill：

```text
adaptive-learning-orchestrator
├── goal-success-contract
├── domain-evidence-landscape
├── capability-concept-graph
├── learner-frontier-diagnostic
├── learning-session-planner
├── instructional-content-interaction
└── mastery-and-adaptation                  # 顶层 S7
    ├── mastery-verifier                   # 只产生掌握证据与归因
    └── learner-model-replanner            # 持久化状态并选择下一路由
```

另设横切的 `learning-artifact-quality-evaluator`，但它不是第 8 个流程步骤。它根据 `stage_id` 加载不同量规，对每一步的工件执行质量门禁。

### 8.1 统一移交信封

每个阶段 Skill 至少遵守以下移交结构；这只是公共信封，不能替代七类工件各自的 JSON Schema：

```yaml
schema_version: 1.0.0
stage_id: S1-S7
run_id: string
learner_id: string | null
input_contract:
  artifact_refs: []
  expected_schema_versions: {}

  status: pass | fail
  missing_fields: []
  stale_inputs: []
assumptions: []
requirement_gaps: []
confirmation:
  mode: mandatory | conditional | inform
  trigger: string | null
  questions: []
  response: {}
  status: pending | confirmed | rejected | acknowledged | corrected
  confirmed_at: timestamp | null

  type: artifact_name
  schema_version: string
  artifact_id: string

      evidence: []
      score: number | boolean
      threshold: number | boolean
      passed: boolean

  source_artifact_ids: []
  source_evidence_ids: []

```

### 8.2 七类工件 Schema 的最低范围

正式实现前，应分别物化七份 JSON Schema；不能只保留文档中的要点列表。

| 工件 | Schema 至少要求的核心字段 |
|---|---|
| `goal_success_contract` | 目标、场景、术语/岗位校正、能力阶梯、验收任务、市场能力与评估模式、`external_research_seed`、通过标准、范围、排除项、约束、确认状态 |
| `domain_evidence_landscape` | 范围、术语、`research_run_manifest`、视角、问题、查询记录、来源台账、强制类别覆盖状态、结论—证据映射、JD 能力矩阵、面试/实操评估矩阵、共识、争议、未知项、置信度 |
| `capability_concept_graph` | 节点、边、节点类型、先修强度、能力陈述、评估项、掌握规则、来源追溯 |
| `learner_snapshot` | 学习者和版本、节点状态、证据、错误类型、提示依赖、学习前沿、证据有效期 |
| `learning_and_session_plan` | 有序节点、排序理由、策略、会话、时间、测评、复习锚点、通关标准、确认状态 |
| `session_package_and_trace` | 内容、来源、活动、提示阶梯、交互事件、候选掌握证据、内容质量状态 |
| `mastery_and_replanning_bundle` | 掌握判定、归因代码、模型变更、路由、调整计划、复习计划、证据追溯 |

Schema 还必须统一定义 ID、时间戳、版本、枚举、必填字段、空值语义和向后兼容策略。

### 8.3 学习者模型作为一等状态

学习者模型不能只作为 S7 文本描述中的“更新后结果”。Skill 实现必须提供：

- `load(learner_id, as_of)`：读取指定时间点的模型和证据有效期；
- `append_evidence(event)`：追加不可变学习证据事件；
- `update(expected_version, patch)`：基于版本的原子更新；
- `history(learner_id)`：审计变更与路由理由；
- 冷启动：返回 `unknown`，由 S4 建立初始证据；
- 冲突处理：检测并发版本，不允许静默覆盖。

## 9. Skill 化前必须补齐的规格与验收门

`gclaude` 对补充强制研究条款前版本的就绪度判断为“中偏低”。下表保留其指出的实现阻塞项，并新增本次 S1–S2 外部研究门；这些补充条款尚未经过该轮 `gclaude` 复核。

| 优先级 | 必须补齐的规格 | 完成判据 |
|---|---|---|
| P0 | 七类工件 JSON Schema | 可由校验器验证必填字段、类型、枚举、版本和追溯关系 |
| P0 | S1–S2 强制外部研究门 | 能验证真实查询记录、联网状态、STORM 视角/问题、必查来源覆盖、来源元数据、结论—证据映射；网络未执行时 G1/G2 必须失败 |
| P0 | 学习者模型持久化与检索 | 支持冷启动、追加证据、版本化原子更新、历史审计和冲突处理 |
| P0 | S7 确定性决策树 | 每个主归因都有唯一默认路由；多归因优先级明确；路由可测试 |
| P0 | 量规阈值 | 每个质量维度具有证据、评分、阈值和三态判定逻辑 |
| P1 | 确认交互状态机 | 三种模式、升级触发、记录字段和阻塞行为可测试 |
| P1 | 阶段输入校验 | 每个阶段拒绝错误类型、过期版本或未通过质量门的上游工件 |
| P1 | 快速档合并守卫 | S2+S3、S4+S5 的允许与禁止条件可以自动判断或要求人工确认 |
| P2 | 冷启动与空证据路径 | 七个阶段均定义输入缺失、证据为空和无法确认时的安全行为 |
| P2 | 研究级运行条件 | 明确何时要求外部专家复核和纵向延迟复测 |

所有 P0 完成前，可以继续做 Skill 规格设计和原型验证，但不得宣称 SOP 已可可靠自动编排。进入正式 Skill 实现验收时还必须满足：

1. 七个步骤的输入、输出和失败路由没有被隐式删除；
2. 每一步先产出正向工件，再执行该工件的专属质量评估；
3. 工件质量评估与学习效果评估保持分离；
4. S2↔S3、S6↔S7 循环可以实际执行；
5. 每次重规划都能解释证据、状态变更、主归因和下一路由；
6. 简化运行只合并执行，不跳过工件、质量门和追溯记录；
7. S1/S2 的检索可证明真实执行，模型知识只作为假设和查询生成器，不能作为外部来源；
8. Wikipedia/百科、官方/学术、实践、招聘、面试/选拔、反方/前沿来源均有覆盖状态和使用边界；
9. S7 的两个物理 Skill 能以版本化证据契约完成原子反馈事务。

## 10. 最终确定

> **顶层 SOP 继续采用 7 步；5 步是具有显式合并守卫的快速执行档；S7 在实现层建议拆为两个物理 Skill。**

同时保留以下边界：

- 不把“7 个顶层步骤”误写为“只能有 7 个物理 Skill”；
- 不允许 S1/S2 只基于模型自身理解；联网预检、STORM 式调研和证据审计在所有复杂度档位都必须保留；
- 不把 Wikipedia、招聘 JD 或面试题中的任何一类单独当成领域真理，而是按各自用途交叉验证；
- 不再笼统声称所有 8 步方案都过细，S7 拆分是有效竞争方案；
- 不采用任何会删除 G2/G3、G4/G5 或 G6/G7 独立质量门的 6 步标准方案；
- 不把原文 12 个能力组件直接等同于 12 个运行步骤；
- 在 P0 规格补齐前，结论状态保持为 **`pass_with_changes`**。
