## Context

仓库已有七个阶段 Skill、共享项目级 LLM Wiki、`project-state.json`、stage manifest/profile、独立调用合同和阶段内 Gate。当前缺少的是面向用户的统一入口：用户必须先理解阶段职责，再决定调用哪个 Skill；“继续”“我想开始学”“给我制定计划”等自然语言也没有统一、可审计的分发规则。

主控 Skill 运行在现有 Skill 机制内，因此它是软编排控制面，不是独立运行时状态机。可验证状态继续由项目 Wiki、JSONL、`project-state.json` 和各阶段 Gate 持有；主控只选择、委托、核验和提示。

## Goals / Non-Goals

**Goals:**

- 提供一个可显式调用、也可被自然语言触发的统一入口。
- 根据用户语义、显式阶段要求和项目当前 `route_to` 选择 S1–S7。
- 复用目标阶段的完整 `SKILL.md`，不在主控中复制阶段业务实现。
- 在阶段调用后重新读取落盘事实，给出明确的下一动作、停顿原因和所需用户输入。
- 对单阶段请求和用户明确要求的完整流程采用不同推进策略。

**Non-Goals:**

- 不创建 S0/G0 或第八个业务阶段，不接管 G1–G7。
- 不用主控的自然语言声明代替联网研究、用户确认、真实学习者回答、迁移或延迟保持证据。
- 不新增脚本、服务、数据库或严格工作流引擎。
- 不修改 S1–S7 当前项目 Wiki 交付合同。

## Decisions

### 1. 主控是薄控制面，阶段 Skill 仍是业务权威

主控包命名为 `.agents/skills/al-orchestrate-personalized-learning/`。它先读取共享合同与最新 manifest/profile，再读取并执行所选阶段的 `SKILL.md`。路由表只保存“意图类别 → 阶段”的选择规则和停止条件，不复制阶段文件清单、量规或领域流程。

替代方案是把七阶段正文合并进主控；这会造成合同漂移、上下文膨胀，并让阶段独立调用失去意义，因此不采用。

### 2. 显式意图、继续意图和语义意图分层解析

选择优先级为：

1. 目标实质变化或新的学习项目始终路由 S1；
2. 用户显式指定 S1–S7 时选择该阶段；
3. “继续/下一步/接着学”读取项目当前已验证 `route_to`；
4. 其他请求按研究、建模、诊断、规划、教学、掌握验证的语义映射；
5. 纯状态查询只读汇总，不执行业务阶段。

多个项目都可能匹配、或两个阶段的选择会产生不同写入时，先请求最小澄清。不得用文件修改时间猜测用户目标。

### 3. 区分单阶段委托与引导式全流程

- 默认 `single_stage`：只执行一个选定阶段；若前置失败，保留该阶段独立调用的 blocked/route 结果并告诉用户恢复动作。
- 用户明确说“从头完成、补齐前置、按完整流程推进”时使用 `guided_flow`：从最早缺失或失效阶段开始，逐阶段执行；每个阶段完成后重新核验，再决定能否继续。

`guided_flow` 遇到 mandatory/升级确认、真实学习者回答、关键选择、联网阻断、版本冲突、pending/blocked、同阶段返工或 S7 回路时立即停下。没有新证据时不得在一个调用中循环重试同一阶段。

### 4. 调用结果以落盘状态为准

主控不得仅根据子 Skill 的口头结论声称执行成功。委托后重新读取项目 `INDEX.md`、`project-state.json`、阶段 `INDEX.md`、`gate.md`、`verification.md` 和本次 conversation；核对 revision、stage state、Gate、`route_to`、必需输入和验证状态。

如果委托没有产生预期落盘事务，应报告 `not_executed` 或证据缺口，不得自行补写阶段正向工件。

### 5. 每次返回统一的下一步回执

用户回执固定包含：项目与 revision、理解到的意图、实际选择/执行的阶段、选择原因、阶段/Gate 状态、证据入口、停止原因、需要用户提供的内容和下一动作。下一动作继续指向主控 Skill，使用户无需直接记忆七个子 Skill 名称。

## Risks / Trade-offs

- [Skill 只能提供软编排，无法保证跨进程原子性] → 明确以项目 revision、事件和 Gate 为权威；未来若要求严格重试/并发控制，再引入外部 harness。
- [意图可能同时涉及多个阶段] → 以最早污染/最早事实所有者优先，并在高影响歧义时澄清。
- [主控与 stage profile 漂移] → 路由时动态读取 manifest/profile；参考文件只保存选择原则和 Skill 名映射。
- [完整流程可能形成 S7→上游回路] → 遇到回路或同阶段返工即停，展示恢复条件，不做无证据自动循环。
- [额外入口增加 Skill 清单噪声] → 使用清晰的 `al-` 命名和宽触发描述，并明确它不是 stage。
