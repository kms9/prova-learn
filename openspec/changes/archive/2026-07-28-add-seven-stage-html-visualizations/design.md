## Context

S1—S7 当前通过字节一致的共同移交信封传递状态、输入校验、证据、处理记录、正向工件、质量评估与下一步路由。每个阶段正向工件的结构不同，JSON 适合作为机器契约，却缺少适合人类探索的表现层。

本变更跨七个 repo-local Skill，必须同时满足：

- Skill 被单独复制后仍然自包含。
- JSON 继续作为唯一权威工件和下游消费格式。
- HTML 可通过 `file://` 离线打开，不依赖构建工具、服务器或第三方包。
- 阻断和待确认结果也能被人类查看。
- 页面中的本地操作不能越权变成确认、教学事件或掌握证据。
- 输入 JSON 视为不可信数据。

持久需求基线见 `docs/chat_log/七阶段Skill输出HTML可视化与交互需求.md`。

## Goals / Non-Goals

**Goals:**

- 以共同单文件模板提供一致外壳和 S1—S7 专属视图。
- 给共同移交信封增加可校验的表现层元数据。
- 支持嵌入 JSON 和用户明确选择本地 JSON 两种装载方式。
- 支持总览、过滤、按需详情、追溯、原始 JSON 和草稿导出。
- 给图形提供文本或表格等价表达，并实现键盘可用的标签页。
- 通过静态检查、Schema、浏览器路由和交互冒烟形成可复验证据。

**Non-Goals:**

- 建设在线应用、部署站点或引入后端服务。
- 在浏览器中复制阶段业务规则或门禁算法。
- 让 HTML 成为下游 Skill 的首选输入。
- 让页面直接修改或保存回权威 JSON。
- 引入框架、CDN、打包器或独立生成脚本。
- 以自动化冒烟宣称完整 WCAG 或真实辅助技术验收。

## Decisions

### 1. JSON 权威，HTML 单向派生

HTML 由完整移交信封派生，而不只由 `positive_artifact` 派生。这样成功、`needs_confirmation` 和 `blocked` 都可被渲染。页面内状态只影响显示，用户输入只可导出为 `unsubmitted_user_draft`。

替代方案是把 HTML 变成可编辑主工件。该方案会产生双真值源、绕过 Schema 和门禁，并混淆“用户在页面输入”与“阶段已经观察到”，因此不采用。

### 2. 共同信封升级为 1.1.0

共同 Schema 新增必填 `presentation_artifact`：

- `format` 固定为 `html`。
- `status` 为 `generated`、`failed` 或 `not_requested`。
- `authority` 固定为 `derived_non_authoritative`。
- `source` 记录阶段、运行、信封版本和可选正向工件标识。
- `interaction_mode` 固定为 `draft_export_only`。
- `validation` 分别记录 HTML 解析、无障碍冒烟和交互冒烟。

使用 JSON Schema 条件约束保证：

- `generated` 时有路径和生成时间，且 `reason=null`。
- `failed` 时路径和生成时间为空，且有失败原因。
- `not_requested` 时路径和生成时间为空，并说明原因。

不把 HTML 生成成功作为阶段业务门禁的一部分；调用明确要求 HTML 时，由任务完成度而非阶段掌握逻辑报告失败。

### 3. 七份字节一致的自包含模板

每个 Skill 携带 `assets/stage-report.html`。模板内部以 `stage_id` 分派阶段渲染配置和字段提取逻辑。七份文件保持字节一致，并以哈希验证。

替代方案一是仓库级共享模板。它减少重复，但 Skill 被单独复制后会失效。替代方案二是七套独立页面，短期直观但会导致安全、无障碍和交互行为漂移。共同自适应模板在自包含和一致性之间更合适。

### 4. 无构建的安全数据嵌入

模板包含唯一的：

```html
<script id="stage-data" type="application/json">{}</script>
```

Skill 只替换该数据块中的 `{}`。序列化 JSON 在写入前转义 `<`、U+2028 和 U+2029。渲染器使用 `textContent`、`createElement` 和属性白名单，不使用 HTML 字符串注入、动态代码执行或网络请求。

模板通过 CSP 元信息禁止远程连接、对象、框架、表单和基址变更。由于单文件要求需要内联样式和程序脚本，CSP 对这两类内联资源作最小例外，但禁止 `eval`。

### 5. 原生 DOM 与 SVG

不引入可视化依赖。列表、表格、条形图、时间线和流程使用语义 HTML；S3 图谱需要关系探索时使用原生 SVG。所有 SVG 都有标题、描述和邻接表等价视图。

这降低离线依赖和供应链风险，代价是布局能力有限。首版以准确关系、高亮和详情为目标，不追求大型图计算或力导向动画。

### 6. 共同外壳，阶段专属核心视图

共同标签为总览、阶段详情、证据与追溯、质量与门禁、原始 JSON。阶段专属配置定义标题、主集合、默认可视化、筛选字段和草稿动作：

- S1：能力与通过规则。
- S2：研究覆盖、主张与证据。
- S3：三层大纲、单元—节点映射与关系图。
- S4：节点状态、前沿和诊断证据。
- S5：学习路径、会话、测评与复习锚点。
- S6：教学内容、活动、提示阶梯与交互轨迹。
- S7：掌握维度、模型差异与路由。

未知或新增字段仍可在原始 JSON 和通用详情中访问，但不能替代专属视图。

### 7. 可访问的渐进增强

首屏和关键数据以语义 HTML 呈现；JavaScript 提供装载、筛选、标签和导出增强。图形含文字总结与表格等价物。标签页遵循 APG 键盘模型，并使用可见焦点、非颜色状态、响应式重排、打印样式和减少动态效果偏好。

### 8. 不新增独立生成脚本

生成步骤写入各 Skill 的引用契约和执行说明，由执行 Skill 复制模板并替换唯一数据块。验证优先使用已有 CLI、浏览器控制和直接命令。这样符合当前仓库偏好，也避免为一次模板替换引入额外维护面。

## Risks / Trade-offs

- [七份模板可能漂移] → 验收时比较七份 SHA-256；任一不一致即失败。
- [单文件模板体积增加] → 复用阶段配置和通用 DOM 构造器，避免嵌入第三方库。
- [CSP 允许内联脚本与样式] → 禁止网络、对象、框架、表单和 eval；输入只走安全 DOM API，并执行危险汇点静态扫描。
- [浏览器中输入被误解为证据] → 页首、输入区和导出文件都标记 `unsubmitted_user_draft`；不提供反写按钮。
- [复杂 S3 图谱在大数据量下降级] → 默认概览和过滤后子图，精确信息始终保留在邻接表。
- [自动化无障碍测试不完整] → 只报告已运行的键盘、语义、对比度和重排冒烟；真实屏幕阅读器人工验收列为独立门禁。
- [1.0.0 消费方不认识新字段] → 明确版本升级；1.0.0 保持可识别但不得按 1.1.0 校验。
- [HTML 失败与阶段状态混淆] → 表现层状态独立记录，不重写阶段业务状态；任务汇报单独说明。

## Migration Plan

1. 冻结 `presentation_artifact` Schema 和三个状态的条件约束。
2. 将七份共同信封 Schema 同步升级为 `1.1.0` 并验证字节一致。
3. 给七个 Skill 增加共同 HTML 契约和共同模板。
4. 更新七个 `SKILL.md` 的输出流程、失败语义和验证要求。
5. 用 S1—S7 最小信封、待确认信封和阻断信封执行验证。
6. 保留现有阶段正向工件 Schema，不做无关迁移。

回滚时可移除 HTML 引用、模板和 `presentation_artifact`，并把共同信封恢复到已保存的 `1.0.0` 内容；阶段正向工件无需回滚。
